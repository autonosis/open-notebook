# Large notebook chat context

Notebook chat previously forwarded selected full sources verbatim, which overflowed provider input context for a 3.7-million-character book. At over 100,000 aggregate context characters the chat graph now selects original-text evidence for the current question, combining scoped vector similarity over indexed chunks with lexical windows and a document-opening excerpt. Selection stays inside the explicitly included sources. Explicit insights-only choices remain insights-only, and generated insights are marked secondary. Small context remains unchanged. Returned checkpoint state stores the bounded selected context.

Retrieval is not exhaustive. Counts, absence and global-document claims require an explicit supporting source statement; the prompt warns against inferring them from retrieved samples. Original source IDs and chunk/character positions are retained. If embedding retrieval fails, original-text lexical evidence remains available. This policy targets the configured DeepSeek deployment; a smaller-context local model can require a lower budget. Existing conversation history is retained and is not independently budgeted by this change. Source Chat has its separate existing context policy.

Validation: production image build and 19 focused tests passed, including selected-source query scoping, original evidence retention, aggregate budget, unchanged small context, insights-only preservation and lexical fallback on embedding failure. A real notebook API request with the full book selected answered “how many PGMs does the book document?” without a context error, citing the source and distinguishing the 31-card Appendix A inventory from broader variants/capabilities. The private verification session and response remain in local data/evidence; no document text is committed here.
