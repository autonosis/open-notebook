# Podcast pipeline observability

Podcasts → Episodes → Details → Summary now begins with Processing pipeline. Active episode lists refresh every three seconds. The panel shows stage, overall/stage elapsed time, script sections, audio clips actually saved, current clip, last update, job ID, exception type and an expandable timeline with stage durations. No estimated percentage or ETA is invented.

The worker observes pinned podcast_creator.nodes Loguru events under an episode ContextVar. Only fixed stage names, counts, identifiers and timestamps are persisted; script content and section titles are not copied into progress records. Progress files are private atomic JSON under application data/observability/podcasts. This bind mount survives container replacement and is included in application-data backups. A progress-write failure cannot abort paid generation. Profile/model settings remain visible in the existing Details sections. Episode-list/detail responses expose pipeline_progress under the same existing API authentication.

Progress begins after the episode record exists. Pre-record validation/queue errors still rely on job status. Timings and counts describe observed work, not audio quality or source fidelity. A stalled stage has an old last-update timestamp; a reliable remaining-time estimate is not available. Historical episodes without records explicitly show unavailable stage history.

The current completed episode predates instrumentation: its real timestamps and 64 saved audio clips were recovered from the original single-worker logs with deployments/macos/backfill_podcast_progress.py. The script accepts logs on stdin plus an episode ID and UTC start timestamp; only use it for a verified single-worker interval. No episode was regenerated to populate telemetry. Old episodes are not automatically backfilled. New generation uses the runtime log sink directly. This release adds visibility, not podcast audio checkpoint/resume.

Validation: production Next/TypeScript build and targeted Ruff pass; 22 focused backend tests, 30 existing podcast regressions and 3 existing EpisodeCard tests pass. Tests exercise event stages, counters, episode isolation, persistence reads, malformed identifiers, context-scoped log ingestion and non-fatal telemetry writes. Actual completed-episode API and browser Details showed 5/5 script sections, 64/64 clips, 13m7s total and stage timings. The progress record survived backend container replacement. A newly generated podcast with the new sink has not been run end-to-end; that integration has focused sink tests and the pinned real-log backfill evidence. Private screenshots/logs/episode content are excluded from Git.
