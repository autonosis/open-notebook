# Persistent PDF batch checkpoints

The previous bounded extraction hook removed `fmt` but still used it in the returned metadata. This raised NameError after conversion, causing the retry decorator to repeat the entire PDF. The hook now retains the format assignment; a regression test calls the actual patched processor through its return statement.

Completed page batches are atomically saved under the persistent application data directory, `extraction_checkpoints/<fingerprint>/<start>-<end>.json`. The key includes PDF bytes, output format, batch size, OCR/formula/vision settings, Docling version, cloud model/provider identifier, and the integration code digest. Credentials are excluded. A payload checksum rejects corrupted entries. A failed or partial conversion is never saved. Changing the PDF or relevant settings starts a distinct cache. Files are private and contain extracted document content: include them in private backups, never commit or publish them. They are retained until explicitly removed while jobs are idle; disk use grows with extracted content.

Retries reuse completed batches in source order, without re-running OCR or cloud enrichment for those batches. A partly completed batch can still repeat its model calls. There is no per-figure request checkpoint, cross-device cache, or downstream transformation checkpoint in this change. Two settings-identical PDFs may reuse extraction; the cache is internal to this single-user deployment. API progress exposes cached_pages. Failed processing attempts record exception type and location without dumping document text or credentials. Retry attempts are bounded to three; programmer errors NameError/TypeError/AttributeError stop immediately.

Validation: ten focused tests pass, including interrupted-run resumption, zero conversion calls for a fully cached rerun, changed PDF/settings invalidation, corrupted checkpoint rejection, partial-conversion rejection, and the actual patched processor return. They do not establish full-book extraction, embedding or transformation completion. The prior in-memory batches cannot be recovered; the first run with this version starts a new cache.
